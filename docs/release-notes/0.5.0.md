# Percona Binary Log Server 0.5.0

Percona Binary Log Server 0.5.0 adds a MySQL-compatible listener to `pull` so downstream clients can read the archived binary logs.

`binlog_server version` prints `0.5.0`. This build is the current upstream `main` line. A release tag has not been published, so this note has no release date.

[Get started with Percona Binary Log Server](../get-started.md) covers the first archive. The commands are unchanged: `version`, `fetch`, `pull`, `list`, `search_by_timestamp`, `search_by_gtid_set`, and `purge_binlogs`.

## Upgrade

Every configuration file needs a `replication_source` section. The server rejects a file that omits it, including a file used only by `fetch`, `list`, `search_by_timestamp`, `search_by_gtid_set`, or `purge_binlogs`. The listener binds to `replication_source.port` only while `pull` is running. Add this object beside the existing top-level sections:

```json
"replication_source": {
  "port": 3307,
  "server_id": 142,
  "server_uuid": "00000000-0000-0000-0000-00000000008e",
  "read_timeout": 60,
  "write_timeout": 60,
  "authentication": {
    "user": "rpl_user",
    "password": "rpl_password",
    "plugin": "caching_sha2_password"
  }
}
```

`port`, `read_timeout`, and `write_timeout` must be greater than 0. `server_uuid` must be a canonical 8-4-4-4-12 hexadecimal UUID. `authentication.user` and `authentication.password` must be non-empty, and `authentication.plugin` must be `caching_sha2_password`.

`replication_source.server_id` and `replication_source.server_uuid` are the identity shown to downstream replicas. They are separate from `replication.server_id`. Choose values that differ from every downstream replica's own `server_id` and `server_uuid`. A replica stops its I/O thread when it detects that loop.

`auth_rsa_private_key` is optional. Set it to the path of a PEM RSA private key when a downstream client authenticates with `caching_sha2_password` over the unencrypted listener. The listener has no TLS settings of its own.

## New features

* **PBS-3**, **PBS-8**, **PBS-37**, **PBS-42**, **PBS-53**, **PBS-90**: `pull` accepts downstream clients on `replication_source.port` while it continues to archive from the upstream server. The listener serves `mysqlbinlog --read-from-remote-server` and a MySQL replica started with `SOURCE_AUTO_POSITION = 0`. It answers the replica I/O handshake, then streams events with `COM_BINLOG_DUMP`. A dump that reaches the end of the archive stays open and waits for new events. `@@GLOBAL.GTID_MODE` follows the storage: `OFF` for a position-mode archive and `ON` for a GTID-mode archive. GTID auto-position (`SOURCE_AUTO_POSITION = 1`) is unsupported in 0.5.0.
* **PBS-6**: Storage can be read while `pull` is writing, which is what lets a downstream client dump events during an active archive.
* **PBS-32**, **PBS-33**, **PBS-34**, **PBS-10**: The listener account uses `caching_sha2_password`. A client that offers another plugin is asked to switch. The first successful login in a process uses full authentication with the configured RSA key. The client can supply the public key locally or request it from the listener. Later logins for that user in the same process use the fast path. One user and password are accepted.
* **PBS-30**: While a blocking dump is idle at end of file, the listener sends `HEARTBEAT_LOG_EVENT_V2` at the period from `SET @source_heartbeat_period`. A period of 0 disables heartbeats. A heartbeat is sent only after the stream has a binlog position to report.
* **PBS-54**: `COM_BINLOG_DUMP` decrypts an encrypted archive before sending events, so the downstream client receives plaintext. Binlog encryption itself was added in 0.4.0.
* **PBS-59**: On startup, `fetch`, `pull`, and `purge_binlogs` remove leftovers from an interrupted rotation, an interrupted purge, or an interrupted creation of the first binlog, and only after the rest of the storage checks out. `binlog.index` is the set of binlog files. Each binlog metadata file is the size of that data file. The newest data file is truncated to the recorded size, including an encrypted file. Any other object that is absent from the index leaves the storage unchanged and startup fails. `list`, `search_by_timestamp`, and `search_by_gtid_set` stay read-only and skip this repair.

## Bug fixes

* **PBS-69**: `storage.checkpoint_size` and `storage.checkpoint_interval` are applied again. They were dropped during the 0.5 storage rewrite and were not part of the 0.4.1 behavior.
* **PBS-79**: Startup no longer crashes when `binlog.index` is empty.
* **PBS-91**: A downstream client that connects before any binlog has been stored stays connected and waits.
* **PBS-99**: When a dump rolls into a binlog that contains only the 4-byte magic, the listener emits the artificial `ROTATE` that names that file at position 4. `mysqlbinlog --raw` then keeps the new file name after a source restart or crash.
* **PBS-64**, **PBS-65**: A dump read that stops in the middle of an event retries with a larger buffer and reuses the bytes already read, so the client receives a complete event.

## Builds and packaging

* The project builds as C++23. The 0.4.1 release built as C++20.
* EL8 packages depend on OpenSSL 3.
